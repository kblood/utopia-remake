# Sound effects: descriptors, samples, the play routine and its call sites

No original audio assets are stored in this repository. This note records the original's addresses, data layout and traced behavior; `parseSfxBank` reads the user's `Disk.1` at run time, `SfxScheduler` in `src/audio/sfx-scheduler.ts` models channel ownership, and `createSfx` plays through WebAudio. Tests: `test/sfx.mjs`, `test/music-pause.mjs`, `test/audio-ownership.mjs`. Addresses are game-image addresses (`game-proper.md`: sectors `$14C`-`$208` loaded at `$1000`, file offset = address + `$28800`). Tags: **VERIFIED** = read directly from disassembly or data, **HYPOTHESIS** = inferred.

## Verdict (VERIFIED)

The game **does** have sound effects, but only six. They are Paula sample playbacks started outside the module player. A scan of the whole game image for the audio registers `$DFF0A0-$DFF0DF` finds writes only in the vertical-blank tick `$1264` (the effect starter, `$12B0`-`$13B2`) and in the module player (`$15F4`-`$1A7C`, which uses a register base). `$DFF096` (DMACON) writes elsewhere in the game are only the display DMA (`$100`/`$8100`), the loader, and the effect/music channel switch-off. There is exactly one entry point, `$11B4`, with 19 call sites; every one loads one of six descriptors. No effect data exists on `Disk.2`/`disk.4` (the scenario disks hold graphics, maps and text only) and none in the boot stage (the boot stage only plays a module).

### Samples

- **Raw samples on `Disk.1`, sectors `$368`-`$386`** (31 sectors, 15,872 bytes, no packing). Loaded to `$2227A` by `$7D3E` (called from the init code at `$1579A`). Signed 8-bit, no header. Sample A = bytes 0..9011 (ids 0-2 play it at three pitches), sample B starts at 9012 (address `$245AE`, id 3). Sample B's descriptor length (7120 bytes) is longer than the 6860 bytes that remain in the region, but the 47-frame duration at period 544 only plays 6129 bytes, so the end is never reached (tested). The loader reads this region and the effects never touch other disk data.
- **8-byte sine cycle at `$14E0`** inside the game image (`0, 90, 127, 90, 0, -90, -127, -90`): the "sample" for ids 4 and 5. Looped by DMA, so id 4 is a 20 ms blip at about 703 Hz and id 5 a 220 ms tone at about 652 Hz.

### Playback rules (VERIFIED from `$11B4` and `$1264`)

- There is no end-of-sample logic: DMA restarts at `AUDxLC` after `length` words, so a sample that is shorter than its duration loops. Every duration in the table is shorter than the data, except the two sine effects which loop on purpose.
- The timer is decremented once per vertical blank right after the start and again every frame; when it reaches 0 the channel's DMA bit is cleared **only while the music is inactive** (`$13E4`/`$141A`/`$1450`/`$1486`; with music active `$13C6`-`$13D8` calls player command 8 instead and writes no DMACON, see "Channel ownership"). A duration field `n` therefore sounds for `n - 1` frames. Frame rate 50 Hz (the slave forces `$910` = 50).

## The play routine `$11B4` and the VBL starter (VERIFIED)

Flags byte `$1581` (image default `$04`): bit 0 extra memory, bit 1 music active, **bit 2 effects enabled** (default on; toggled by the music-menu button at `$10BC`, whose messages are the "Effects on."/"Effects off." strings 404/405), bit 3 explosion variant (below), bit 4 loading (`$111E`-`$1132`), bit 5 the QoL title flag flipped once per main-loop pass by `bchg #5` at `$4DCA` inside `$4D96` (not a sound flag; game-text.md section 8, VERIFIED statically).

`$11B4` (a6 = descriptor, caller loads `d0 = byte $1582`, which the routine ignores):

1. Return if bit 2 of `$1581` is clear. Disable the VBL interrupt (INTENA `$20`) while working.
2. **Music active (bit 1):** (the test is the active bit, not the loaded track `$1580`: the music on/off button `$1062` clears bit 1 and leaves `$1580`, after which step 3 applies although a track is still selected, see `music.md`) the track's flags word (`$1582` high byte, `$1583` low byte; `$103`, `$203`, `$102`, `$103` for tracks 0-3) names two Paula channels the effects may use. Try the first, then the second; a channel is free when its timer word `$1518 + 2 * ch` is 0. If both are busy the request is dropped. On success the module player's voice on that channel is released **at once, at the request** (player command 7 at `$176E`: see "Channel ownership" below for what exactly it clears) and handed back when the timer ends, **but only if the music is still active then** (command 8 at `$1794`; otherwise the module voice is never handed back). The earlier wording "restored when the timer ends" was too coarse (CORRECTED by the 2026-11-07 re-trace below).
3. **No music:** channels 0, 1, 2, 3 in that order, first free one; all busy = dropped.
4. The descriptor pointer is stored in the one-entry queue `$1520 + 4 * channel`.
5. Re-enable the VBL interrupt.

The VBL handler `$1264` (after the module tick) starts **at most one queued effect per frame**, lowest channel first (`$129C`-`$13B2`): writes `AUDxLC`, `LEN`, `PER`, `VOL`, sets the timer from +10 and turns the DMA bit on; then it runs the four timers (`$13B6`-`$1486`).

Consequences, all VERIFIED from the code and modelled by `SfxScheduler`:
- A channel counts as busy only once the effect has really started (timer non-zero). Two requests within one frame therefore pick the same channel and the second replaces the first in the queue. This makes the double alert at `$117AE`/`$117C0` a single alert.
- Up to two effects at once while music plays (channels from the flags word), up to four otherwise. Panning follows Paula: channels 0 and 3 left, 1 and 2 right.

## Channel ownership, interruption and cancellation (static re-trace 2026-11-07)

### State

| Item | Address | Meaning |
|---|---|---|

| `Q[ch]` | `$1520 + 4 * ch` | one-entry queue: descriptor pointer or 0. Written only by `$11B4` (`$1254`), read and cleared only by `$1264` (`$12A4`-`$12AA`, `$12EC`-`$12F2`, `$1334`-`$133A`, `$137A`-`$1380`) |
| pair | `$1582` / `$1583` | first / second channel the effects may use while music is active (from the loaded track's table word) |
| `E[ch]` | word at `+4` of the player's channel record (`$2510`, `$2542`, `$2574`, `$25A6` = base `$2300` + `$210`/`$242`/`$274`/`$2A6`) | "the module owns this Paula channel": image default `1`, `2`, `4`, `8`. **Written only by command 7 (`$1780`, `clr.w`) and command 8 (`$17A4`, copies the channel's mask word from the table `$1948`: `$0210/1`, `$0242/2`, `$0274/4`, `$02A6/8`).** A scan of `$1608`-`$22FF` for destinations of the form `$4(aN)` finds no other write; cmd 0 (`$1608`) and cmd 1 (`$16D0` = `$195E` + `$19FE`) do not reset it |
| `D` | word `$250C` | DMA bits the tick re-asserts; set at a note trigger (`$1D16`), cleared bit-wise by command 7 (`$178E`), zeroed by the module init `$195E` (`$19F8`) |

`$158A` has exactly seven call sites: `$1190` (cmd 0) and `$11A4` (cmd 1) in the loader, `$1242` (cmd 7) in `$11B4`, `$13D8`/`$140E`/`$1444`/`$147A` (cmd 8) in the timer code. `$1062`, `$10BC` and `$110A` have no direct caller (they are reached through the disk-menu table `$7FE4` and `$8A42`). Command number to routine: table `$15F4`, entry `n` at `$15F6 + 2n`, target = `$15F6 + word - 2`, so cmd 7 = `$176E`, cmd 8 = `$1794` (VERIFIED, matches the earlier note).

### What each routine does, in order (VERIFIED)

- **Request `$11B4`** (VBL interrupt masked with INTENA `$20` for the whole routine): (1) bit 2 clear: return, nothing queued. (2) bit 1 set: candidates are byte `$1582`, then byte `$1583` (`$11D4`-`$11F6`); the first whose `T` is 0 wins; both non-zero: return, the request is dropped and nothing is touched (`$11F8`). (3) bit 1 clear: candidates 0, 1, 2, 3 (`$1204`-`$122A`); all non-zero: dropped. (4) With the channel chosen and bit 1 set, **command 7 runs immediately** (`$1240`-`$1242`): `E[ch] = 0`, DMACON written with the channel's bit and bit 15 clear (the channel's DMA goes off), `D &= ~bit`. (5) `Q[ch] = descriptor` (`$124C`-`$1254`), overwriting an entry that had not started yet, without flag or cleanup. A busy test looks only at `T`, never at `Q`, so a pending entry does not make its channel busy (this is the double-alert quirk).
- **VBL `$1264`**: (1) bit 1 set: the module tick (every 6th skipped on a 60 Hz machine). (2) bit 2 clear: return at `$1298`/`$148E`: **no queue start and no timer decrement** while effects are disabled. (3) otherwise start at most one entry, channels in order 0..3 (`$129C`, `$12E4`, `$132C`, `$1372`): clear `Q[ch]`, write AUDxLC/LEN/PER/VOL from the descriptor (volume read here, at the start, from the descriptor's `+8`), `T[ch] = descriptor +10`, DMACON set bit. (4) Then always (`$13B6`-`$1486`) for each channel with `T != 0`: decrement; when it reaches 0: **bit 1 set -> command 8 (`E[ch] = bit(ch)`), no DMACON write at all** (`$13C6`-`$13D8`); bit 1 clear -> DMACON clear of the channel's bit (`$13E4`).
- **`$1062` music off** (bit 1 set): clear bit 1, DMACON `$000F` (all four Paula channels off, effect voices included), `$1580` kept. `T`, `Q`, `E`, `D` are untouched. **On** (bit 1 clear, `$1580 >= 0`): set bit 1, nothing else.
- **`$10BC` effects off** (bit 2 set): clear bit 2, `T[0..3] = 0` (`$10E4`-`$10F6`), DMACON `$000F`. `Q` is NOT cleared and command 8 is NOT called, so `E` stays whatever it was. **On**: set bit 2, nothing else.
- **`$110A` track load** (row < 4): set bit 4, `$8A4C`, clear bit 1, clear bit 4, DMACON `$000F`, store `$1580`/`$1582`, read and unpack, cmd 0, cmd 1, set bit 1. `T`, `Q`, `E` untouched (no same-track test, see `music.md`).
- Other DMACON writers in the sector range: the display (`$7FFF` at `$2AB2`/`$2B4A`, reached from the init chain only: `$2B1A` callers `$15702` and `$4E3C`; `$4E28` has one caller, `$157A8`; `$0100`/`$8100` bitplane DMA at `$4E2A`, `$157A0`, `$15708`, `$7EDA`) and the player itself (`$195E` init `$000F`, tick `$1B22` set, `$1D12` retrigger clear).

### Consequences (VERIFIED from the code unless marked)

1. **The module voice is released at the request, not at the effect start**: up to one frame before the effect sounds, the channel is silent.
2. **Hand-back is conditional.** If the music is switched off (`$1062`), the track is reloaded, or effects are switched off (`$10BC`) while an effect owns a channel, the expiry (or `$10BC`'s clear) never runs command 8: `E[ch]` stays 0 and the module voice on that channel stays silent (no period/volume/DMA writes, retriggers skipped) until another effect takes that channel while the music is active and expires. A track reload does not repair it (`$158A` cmd 0/1 never write `E`). Reachable in play (a 2 s explosion running while the pause icon is released) but rare; the click blip of the icon press itself lasts one frame and is over before the release. Remake status: modelled as traced (`SfxScheduler.moduleEnabled`), flagged as a static-only reading below.
3. **Music off, track reload and effects off cut the effect audio but not its timer.** DMACON `$F` stops the sample at once; `T[ch]` keeps counting (`$1062`, `$110A`) so the channel stays busy until the original end, or is zeroed (`$10BC`). Queued entries survive all three.
4. **Effects off freezes the starter.** An entry still in `Q` when `$10BC` clears bit 2 is not started (`$1298`) and is not dropped; it starts at the first VBL after the effects are enabled again, with a fresh timer. Requests are refused (`$11B4` step 1) while disabled.
5. **A same-frame pair of requests on one channel is one voice** (existing finding): `Q[ch]` is overwritten, and command 7 simply repeats.
6. **Expiry under music leaves the effect's DMA running** (HYPOTHESIS, hardware consequence): `$13C6`-`$13D8` writes no DMACON, command 8 only sets `E`, and the module's `D` bit was cleared by command 7 and is not restored. So until the module's next note trigger on that channel (`$1D16` sets `D`), the effect's own sample keeps playing, now with the period and volume the tick writes again (`$1ACA`-`$1B06`, once `E != 0`) and, when the sample data ends, Paula reloads AUDxLC/LEN that the tick has been writing from the module's loop fields (`$1B32`-`$1B86`). The descriptors' durations are shorter than the sample data (about 1000-1200 bytes left for ids 0-3; the 8-byte sine of ids 4/5 wraps in microseconds), so this is at most a short tail of the effect sample at module pitch. NOT modelled by the remake (it unmutes the module voice cleanly at the expiry); no capture exists.
7. **Resuming the module after `$1062` off/on** (HYPOTHESIS, replaces the earlier "voices stay silent until the next note"): the tick re-asserts every bit in `D` with DMACON set at `$1B1A`-`$1B22` on every tick, and `D` is not cleared by DMACON `$F`, so the module voices that the effects do not own are switched on again by the first tick after bit 1 is set. They restart from AUDxLC (the tick keeps writing the loop fields there, `$1B32`-`$1B86`), so a looped sample resumes from its loop start and a one-shot sample, whose loop fields name an empty word, is silent until its next note. The remake instead resumes the module bit-exactly where it was (`test/music-pause.mjs`); this is a known approximation.
8. The descriptor is shared memory (VERIFIED static, re-checked 2026-11-10): `$1237C` writes the volume into the descriptor (`move.w #imm,8(a6)` at `$123E6`/`$1242E`, the only such writes in the image; all other descriptor references go straight to `jsr $11B4`), and the starter reads `$8(a6)` when it STARTS an entry (`$12C0`). The write happens before `$11B4`, so it stays even when the request is dropped or refused, and an unstarted entry of the same descriptor sounds at the value written last. A started entry keeps its volume. Practical reach is narrow (see "Re-check 2026-11-10": same-frame requests replace one another on channel 0, so this matters only when pending entries of one descriptor sit on different channels, e.g. after a music switch in the same frame, or when a refused request's write meets a held entry). Remake: modelled since 2026-11-10 (`SfxScheduler.volumeOf` and the `volume` argument of `request`; `test/audio-ownership.mjs`).

### Remake mapping (`src/audio/sfx-scheduler.ts`, `src/audio/sfx.ts`, `src/audio/music.ts`, `src/audio/webaudio.ts`; `test/audio-ownership.mjs`)

- `SfxScheduler` is now a frame-stepped model of exactly the state above (`Q`, `T`, `E`, the music pair as an observation of bit 1, the effects bit). `advanceTo(frame)` runs the VBL steps in order (start at most one entry, lowest channel first, then the timers), and every operation first advances to its own frame, so a state change at frame `f` is seen by expiries at frames `> f` and not by earlier ones. Frame 50 Hz; the audio layer takes frames from `AudioContext.currentTime` (never wall-clock timers).
- Interruptions are events (`take()`): `queued` (a node is to be scheduled at the voice's start frame, re-sent when the predicted start changes), `drop` (replaced or held while effects are off), `start`, `cut` (DMACON `$F`: the sound stops, the timer goes on) and `end` (`expired`, `disabled`, `dispose`). The WebAudio layer is a pure projection of these events onto one cancellable `AudioBufferSourceNode` per voice, so a replaced, cut, disabled or disposed voice can never keep sounding or call back later.
- Module ownership: `moduleEnabled(ch)` is `E[ch]`; `Sfx` mirrors it into `Music.setChannelMuted` (diffed, so it touches only what changed). The state changes at the request frame (cmd 7) and at expiry only under active music (cmd 8). It is applied at audio-block granularity (see below).
- Music transitions reach the model through `Music.onChange` (`dmaOff` true for `$1062` off, a track load `$110A` and `stop()`; false for `$1062` on); a link without that hook is observed at every `play` instead.
- The module's block callback (`Music.onBlock`, driven by the ScriptProcessor's `playbackTime`) advances the model so expiries unmute the module voice on the audio timeline. Granularity is one block (2048 samples, about 46 ms at 44.1 kHz): the mute can start up to one block after the request and end up to one block after the expiry; the original changes at frame (20 ms) granularity. A suspended AudioContext freezes `currentTime` and the blocks, so the model, the effect nodes and the module stay in step (a wall-clock timer would not).
- Shared descriptor volume (consequence 8, modelled 2026-11-10): every explosion request that reaches `$123E6`/`$1242E` writes its volume into the model's descriptor, refused or dropped requests included (`request` writes before the bit-2 and channel checks); a queued entry of that descriptor is re-scheduled (`queued` event) with the new value, a held one takes the value silently, and a started voice keeps the value it started with.
- Not modelled (see also "Not verified"): consequence 6 (effect tail after expiry), consequence 7 (module voice restart from the loop pointer on resume), DMA start latency inside the frame, and any waveform or capture comparison.

Browser output routes both module audio and SFX through the shared Paula bus in `webaudio.ts`. The module player's statically traced `E0x` control therefore switches the same approximate A1200 LED low-pass path for SFX as well as music; standalone `renderEffect()` remains a raw effect renderer for deterministic tests. The filter is a sound-model approximation and has no original waveform comparison (see `music.md`, E0x section).

## API (`src/audio/sfx.ts`)

```ts
const sfx = createSfx(disk1, disk2, { music });   // music: the Music object, optional
sfx.play(SFX.CLICK);                               // id 0..5, optional volume 0..64 (explosions: 64 in view, 32 off screen)
sfx.setEnabled(false); sfx.setVolume(0.8); sfx.resume(); sfx.sync(); sfx.dispose();
```

- Shares the single `AudioContext` of the music (`sharedAudioContext()` in `webaudio.ts`); `Music.dispose()` no longer closes it. Effects are pre-rendered `AudioBuffer`s (cached per id, volume, side) played through their own gain node, so music fades do not affect them.
- With `{ music }` the effects use the allocation rules above: only the two channels of the playing track while music is **active** (`Music.active`, `effectChannelsFor(link)`; a track paused with the music on/off button is still `Music.current` but not active, so all four channels are candidates, lowest first, and no module voice is muted). While it is active the module's voice on the taken channel is muted from the request until the traced hand-back (`SfxScheduler.moduleEnabled`, mirrored into `Music.setChannelMuted`). Without it every effect plays on top of the full music. Interruptions follow the 2026-11-07 trace ("Channel ownership" above): music off (`Music.setActive(false)`), a track load (`Music.play` that loads) and `Music.stop()` cut the sounding effects but not their timers (`Music.onChange`, `dmaOff`); `setEnabled(false)` stops them and clears the timers and holds queued entries; `dispose()` cancels everything and returns the muted voices. All scheduling is on the AudioContext clock (frames of 1/50 s, `AudioBufferSourceNode.start(when)` and one cancellable node per voice, driven by the model's events); the model is advanced by every call and by the music's block tick (`Music.onBlock`), there are no `setTimeout`/`setInterval` timers (`test/audio-ownership.mjs` counts them). `SfxMusicLink.onChange`/`onBlock` are optional: without them the music state is sampled at each `play` and `sync()` advances the model.
- Levels use the module mixer's scale and separation (0.5), so an effect at volume 64 peaks at the same level as a module channel at volume 64.
- `play` is a no-op until the browser allows audio; call it from a click/key handler at least once (or `resume()`).
