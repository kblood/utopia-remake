# Bitmap font, string tables and the credit roll

Verified against the WinUAE reference run: with the title picture decoded and the first 12 characters of one credit string drawn, all 64,000 pixels equal the screen read from emulator RAM.

## Where the data is

All offsets are image offsets in `Disk.1`. The boot stage (image `$3000`-`$87FF`) is loaded to chip RAM at `$77F18`, so RAM address = image offset + `$74F18` for this block.

| What | Image offset |
|---|---|
| Character table: 2 bytes per character code (code - `$20`): glyph index, advance width | `$43A2` |
| Glyph bitmaps: 7 rows of 1 byte per glyph, MSB is the left pixel, glyph indices up to 59 | `$4468` |
| Credit string index list: words, ends with a word with bit 15 set | `$4644` |
| Language string table, English | `$46CA` |
| Language string table, French / German / Italian | `$5356` / `$5FDA` / `$6D98` |

## String tables

- A table starts with an array of 16-bit offsets, one per string, relative to the start of the table. String numbers start at 1.
- Strings are zero terminated. Letters are stored in upper or lower case and drawn as upper case.
- A byte with bit 7 set is a line break: back to the start x, down 9 rows.
- Strings 1-8 are the credit roll lines (padded with spaces). Further strings are help and in-game text; they are not documented here.

## Drawing

- A character is looked up with `code = (c >= 'a' ? c - $20 : c) - $20`. Its glyph is drawn 7 rows high, 8 columns wide, and the cursor advances by the width from the table.
- Only set glyph pixels are painted (the original clears those bits in all five planes and ORs the text colour). The credit roll uses colour index 1.

## Credit roll (title screen)

- Text position x = `$30`, y = `$B4` (180). The boot stage steps through the index list, draws the string one character at a time (2 video frames per character), holds it for 121 frames, clears the band, and moves to the next string. The list is cycled until a mouse button is pressed.
- [V static, 2026-11-09; RAM addresses = image offset + `$74F18`] Per character, `$78A48` calls the wait `$78BB8` with d7=1 (bit 4 of `$79556`, initially `$10` in the image, enables it): two VBL iterations, then the glyph is drawn. The hold is `$78BB8` with d7=`$78` (121 iterations). `$78BB8` clears its VBL flag (bit 0 of `$79556`, set once per frame by the VBL handler at `$78F5E`), reads the buttons with `$78CCC` (bit 0 left, bit 1 right) and returns at once on any non-zero reading.
- [V static] Either button speeds the typing: a press makes each character's wait return after one frame. Either button ends the roll during the hold: the caller at `$78680` treats any non-zero result as a click and goes to the language screen. The right-button branch inside `$78BB8` (to `$78944`) needs bit 5 of `$79556`; that bit is set only by the later `$78912` path, so the roll does not take it.
- The clear erases bitplane 0 only, for 7 rows starting at x = `$28`, 31 bytes wide.
- A press of either mouse button during the hold ends the roll (see the traced rules above). The next step is the language picture (`Disk.1` sectors `$5A`-`$5F`).
- The language choice is made by the pointer's vertical position. The thresholds are `$2C`, `$5B` and `$89`, which pick English, French, German or Italian, matching the four flags in the language picture.
- Buttons are read from CIA-A port A bit 6 (left) and POTGOR bit 10 (right).
- [V static, 2026-11-10, Disk.1 only] What comes before the roll (boot code `$78550`-`$78662`): the logo picture (sectors `$729`-`$733`, decoded to the screen by `$7C846`) fades in (44 VBLs, `$785C4`, pending: see graphics-and-music-blocks.md, "Fade timing"), holds (51 VBLs, `$785C8` with d7 = `$32`), fades out (45, `$785CE`); the title picture (`$70A`-`$728`) fades in (44, `$78610`, pending for the same reason); then track 3 is loaded and started (`$78614`-`$78654`, see music.md); then the roll loop begins at `$78662`. The fades and the hold add up to 184 VBLs (44 + 51 + 45 + 44, about 3.7 s at 50 Hz) from the logo's fade-in to the title fade's last step, where track 3 starts. The roll's first character is drawn in the roll's first update, one VBL after track 3 starts, because its first wait is pending (the track 3 decode `$78634` precedes it); the later characters take 2 VBLs (`$78A48`).
  - [V static, 2026-11-10; remake implementation] `IntroScene` (`src/game/intro.ts`) reproduces the pre-roll. The logo is `PICTURES.presents` (`$729`-`$733`), decoded by the existing picture decoder; its 32 palette words sit after the five planes, so they are the fade target, as the title's are. The title decodes over the logo in the update that ends the logo fade-out. Update numbers from the first update after construction, one update per VBL: logo fade-in steps at 2-44 (first wait pending); hold checks at 45-95 (51 checks; a left or right button ends the hold at that check, its result ignored, the fade-out starts that update); logo fade-out steps at 98-140 (the title decodes in 140); title fade-in steps at 142-184 (pending); track 3 starts in update 184 (`startModule`); the roll's first update is 185, and its first character is drawn in it. The fades read no button, and a button held into the roll types one character per update and clicks at the end of the first line (the roll's click rule above).
  - Checked by `test/intro.mjs` (an independent planar decode of both pictures, the palette after every update, the stage, the pictures at fixed updates, the start update, and presses during the fades, the logo hold and a button held across the title fade) and `test/boot-music.mjs` (track 3 once, at update 184). Both use the user's Disk.1 and synthetic input.
  - Not checked: the pre-roll's pixels, palette and timing are static-trace parity, not compared with a running original or a capture. The module's load and unpack time (`$77F84`, `$7C846`) is not traced and takes no updates here.

## Language screen and what follows (boot stage, verified by disassembly and TypeScript test)

- Click ends the credit roll. The boot stage saves the current palette, fades out (15 steps, 3 frames each, one 4-bit level per channel), decodes Disk.1 sectors `$5A`-`$5F` and fades in the same way. The traced fade is 15 steps of 3 frames each, so 45 + 44 frames (`$78CEC` out, `$78D54` in, whose first wait is pending because the picture decode precedes it; each returns after its last step). The picture is unpacked by `$7C846` and draws no button read. `test/language.mjs` checks the timing and the pixel-identical picture.
- Poll order (static, `$786E0`-`$78700`): `$78D54` returns after the last palette step, then `move.w #$8020,$DFF096`, `bset #2,$79556`, and the poll `btst.b #6,$BFE001` / `bne` at `$786F4`. No other button read lies between the fade and the poll, and none runs during the fades. The poll is level-triggered: it exits as soon as bit 6 reads 0 (pressed), so a button already down chooses at once. The right button is not read. Once it exits, the pointer row is read from `$79106` at that moment.
- Left button (CIA-A port A bit 6) is polled; the pointer row (screen coordinates) selects 0 (English) below 44, 1 (French) below 91, 2 (German) below 137, otherwise 3 (Italian). The choice is stored as a long at chip `$900`, and a pointer to the language's string table is stored at `$7922E` for the French/German/Italian tables.
- **After the choice: the traced boot-stage order (static reading of Disk.1; the remake status is in the last column).** Addresses are RAM addresses of the boot stage. A fade is `$78CEC` (out) or `$78D54` (in): 15 steps, 3 VBLs per step, 45 updates (44 where the first wait is pending: the rows below say which). Each step moves every non-zero channel by one 4-bit level.
